# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Dune: Awakening private dedicated-server owners and trusted remote administrators use DST to operate and support a self-hosted server from a Windows desktop shell or browser portal.

## Product Purpose

DST makes routine server operation, configuration, diagnostics, and gameplay administration understandable and safer without requiring operators to assemble the underlying PowerShell, VM, database, and game-server workflows themselves.

## Operating Context

DST ships as one Windows installer containing a PowerShell HTTP backend, React portal, and WebView2 desktop shell. The same portal supports local owners and permission-limited remote viewers.

## Capabilities and Constraints

Permissions and platform capability checks remain authoritative. Browser-local preferences are intentionally scoped to each browser profile and origin. Preview visualization must be distinguished from live-derived status and cache observations, and must not be presented as live telemetry.

## Brand Commitments

DST is not bound to its original desert-amber appearance. A complete alternative
visual direction may shape its components and interactions while retaining
product truth, clear operational language, and familiar keyboard behavior.
Signal remains an optional skin. The spatial home instead establishes a
software-like object workspace: a large rotatable Arrakis globe with a smooth
pale lavender-gray sphere, separate dusty-lavender stepped terrain, contextual inspection, and
direct tool access. It is not constrained by an example image's colors or
layout. Existing themes remain available. The approved spatial layout extends
through the tool workspaces with shared navigation and a persistent palette
choice: neutral light/dark and Dune-inspired colors. Decorative 3D signal runners
are optional, respect reduced motion, and never imply actual network traffic.
The globe replaces the introductory hero/template. Map emblems occupy the
planet surface; Hagga is the connection hub and Overmap is login context.
Route endpoints use readiness colors (green/red/neutral), blending between
different endpoint states while pulses travel outward from Hagga.
Users can arrange globe emblems in an explicit Move maps mode, with
browser-local saved positions, reset, and keyboard/touch alternatives.
Layouts are visual preferences, never mutations of game geography. Ambiguous
instances must not inherit another instance's saved placement.
Spatial is a viewport-contained operational dashboard, with plain ordered
map/status/count text, a fixed bottom control strip and a separately reserved
dock. Count-only map details overlay the scene without moving it. Camera zoom
is a saved browser preference independent of map placement and interface scale.

## Evidence on Hand

Repository code, tests, documentation, and shipped assets are the source of truth. Sponsor names or product claims must not be invented.

## Product Principles

- Make system state and data provenance explicit.
- Preserve user control and safe operational defaults.
- Keep navigation discoverable across local and remote contexts.
- Prioritize measured performance, then task clarity and expressive visual craft.
- Build coherent components around the chosen visual direction rather than merely recoloring incumbent templates.
- Spatial graphics are optional, loaded on demand, and never imply real game geography without an authoritative source.

## Accessibility & Inclusion

Interactive controls support keyboard use, visible focus, semantic labels, responsive layouts, and touch-sized targets.
